# 분석 모델링 및 평가 발표 요약서

작성일: 2026-06-25

## 1. 목적

본 프로젝트에서는 군용 차량 이미지 데이터를 대상으로 다양한 딥러닝 모델을 비교하고, 최종 프로그램에 적용할 수 있는 모델을 선정하기 위한 실험 환경을 구축했다.

단순히 모델 하나를 직접 실행하는 방식이 아니라, 여러 detector와 classifier 후보를 같은 조건에서 학습하고 평가할 수 있도록 실험 과정을 자동화하는 데 초점을 두었다.

특히 팀 단위 실험에서는 사람이 직접 명령어를 입력하고 결과를 정리하면 실수가 생기기 쉽다. 그래서 모델 선택, 학습 실행, 결과 저장, 성능 지표 확인까지 하나의 흐름으로 관리할 수 있는 실험 플랫폼을 만들었다.

## 2. 활용한 기술 및 구현 방법

실험 플랫폼은 Python 기반으로 구현했으며, GUI를 통해 모델 후보를 선택하고 실행할 수 있도록 구성했다.

주요 기술은 다음과 같다.

| 구분 | 활용 내용 |
|---|---|
| Python | 전체 실험 엔진과 자동화 로직 구현 |
| Tkinter GUI | 팀원이 쉽게 모델을 선택하고 실행할 수 있는 화면 제공 |
| YAML Config | 모델, 데이터셋, 학습 옵션을 파일로 관리 |
| SQLite | 실험 결과와 실행 기록 저장 |
| SSH | Vast AI GPU 서버와 연결하여 원격 학습 실행 |
| PyTorch / Torchvision / timm | classifier 모델 학습 및 평가 |
| Ultralytics YOLO | YOLO 계열 detector/classifier 실행 |
| Docker Runtime 준비 | GPU 서버 환경 차이를 줄이기 위한 배포 기반 마련 |

모델 실행은 직접 코드에 하드코딩하지 않고, config 파일을 통해 관리한다. 사용자가 GUI에서 모델을 고르면 해당 모델에 맞는 설정이 자동으로 적용되고, 실행 결과는 정해진 폴더 구조로 저장된다.

## 3. 핵심 기능

### 3.1 모델 후보 선택

GUI에서 detector 또는 classifier 후보를 선택할 수 있다.

예를 들어 classifier 실험에서는 EfficientNet, MobileNetV3, ResNet, ConvNeXt, YOLO classification 모델 등을 선택해 비교할 수 있다.

detector 실험에서는 YOLO 계열, RT-DETR, LW-DETR, RF-DETR, D-FINE 계열 모델을 비교할 수 있도록 준비했다.

### 3.2 학습 자동화

기존에는 GPU 서버에 접속한 뒤, 코드 업로드, dependency 설치, 학습 명령 실행, 결과 다운로드를 사람이 직접 처리해야 했다.

현재 프로그램에서는 GUI에서 Run 버튼을 누르면 다음 과정이 자동으로 이어진다.

```text
모델 선택
-> 실행 설정 생성
-> GPU 서버 연결
-> 필요한 파일 업로드
-> 원격 학습 실행
-> 결과 수집
-> 성능 지표 저장
```

이 과정을 통해 팀원이 모델마다 다른 명령어를 직접 기억하지 않아도 실험을 진행할 수 있다.

### 3.3 여러 모델 순차 실행

최대 5개 모델을 한 번에 선택해 queue에 등록할 수 있다.

`Run All`을 누르면 첫 번째 모델이 끝난 뒤 두 번째 모델이 실행되고, 그 다음 모델도 순서대로 실행된다. 각 모델은 학습과 결과 수집까지 끝난 뒤 다음 모델로 넘어간다.

이 기능을 통해 팀원이 자리를 비운 동안에도 여러 모델을 연속으로 실험할 수 있다.

### 3.4 원격 GPU 서버 지원

학습에는 GPU 자원이 필요하므로 Vast AI 같은 외부 GPU 서버를 사용할 수 있게 했다.

사용자는 Vast AI에서 SSH 접속 명령어를 복사해 GUI에 붙여넣고, 버튼을 누르면 서버 정보가 자동으로 등록된다.

이후에는 GUI에서 선택한 모델을 해당 GPU 서버에서 실행할 수 있다.

### 3.5 결과 자동 저장

각 실험 결과는 공통된 구조로 저장된다.

저장되는 대표 결과는 다음과 같다.

- 학습 결과 요약
- 성능 지표
- 예측 결과
- 실행 시간 기록
- 학습된 모델 가중치
- detection bbox preview
- classifier confusion matrix

이렇게 결과 형식을 통일해두면 모델별 성능을 비교하거나, 실패 원인을 확인하기 쉽다.

## 4. 성능 평가 방식

모델 종류에 따라 평가 지표를 다르게 사용했다.

### 4.1 Classification 평가

classifier 모델은 crop 이미지가 어떤 차량 클래스에 속하는지 분류한다.

주요 지표는 다음과 같다.

- Accuracy
- Macro Precision
- Macro Recall
- Macro F1-score
- Class Recall
- Label Error Rate
- Confusion Matrix

단순 accuracy만 보면 특정 클래스에서 성능이 낮은 문제를 놓칠 수 있다. 그래서 클래스별 성능 차이를 확인하기 위해 macro 지표와 confusion matrix를 함께 저장하도록 했다.

### 4.2 Detection 평가

detector 모델은 이미지에서 객체 위치를 찾아 bbox를 예측한다.

주요 지표는 다음과 같다.

- Precision
- Recall
- mAP50
- mAP50-95
- 클래스별 AP
- 예측 bbox 수
- GT 객체 수

detection은 단순히 클래스를 맞히는 것이 아니라 객체 위치까지 맞춰야 하므로 mAP 계열 지표가 중요하다.

## 5. 구현 결과

현재 프로그램은 다음과 같은 형태로 동작한다.

- GUI에서 모델 후보를 선택할 수 있다.
- detector-only와 classifier-only 실험을 분리해 실행할 수 있다.
- 모델별 학습 옵션을 GUI에서 수정할 수 있다.
- Vast AI GPU 서버에 연결해 원격 학습을 실행할 수 있다.
- 최대 5개 모델을 queue에 넣고 순차 실행할 수 있다.
- 실험 결과와 학습된 weight가 자동으로 저장된다.
- 성능 지표와 실행 시간이 자동 기록된다.
- classifier 결과에는 confusion matrix가 저장되어 클래스별 오분류를 확인할 수 있다.
- detector 결과는 bbox preview를 통해 실제 예측 위치를 시각적으로 확인할 수 있다.

이를 통해 팀원들이 각자 맡은 모델을 동일한 방식으로 실행하고, 결과를 비교할 수 있는 기반을 마련했다.

## 6. 기대 효과

이번 실험 플랫폼을 통해 얻을 수 있는 장점은 다음과 같다.

첫째, 실험 과정이 표준화된다.  
모델마다 다른 실행 명령어를 직접 다루지 않아도 되며, GUI에서 같은 방식으로 실험을 수행할 수 있다.

둘째, 실험 재현성이 높아진다.  
모델 설정, 데이터셋 경로, 학습 옵션, 실행 결과가 파일과 DB에 기록되기 때문에 나중에 어떤 조건으로 실험했는지 다시 확인할 수 있다.

셋째, 팀 단위 작업에 적합하다.  
여러 팀원이 각자 모델을 맡아도 결과가 같은 구조로 저장되므로 성능 비교와 취합이 쉽다.

넷째, GPU 서버 사용이 편해진다.  
Vast AI 서버를 새로 빌려도 GUI에서 SSH 정보를 등록하고 실행할 수 있어, 서버 연결과 실험 실행 과정이 단순해진다.

다섯째, 모델 선택 근거를 명확히 남길 수 있다.  
accuracy뿐 아니라 macro F1, recall, mAP, confusion matrix, 실행 시간 등을 함께 기록해 최종 모델 선정 근거를 더 객관적으로 제시할 수 있다.

## 7. 요약

본 프로젝트에서는 최종 모델 선정을 위해 detector와 classifier 후보를 체계적으로 비교할 수 있는 실험 자동화 플랫폼을 구축했다.

이 플랫폼은 GUI 기반 모델 선택, GPU 서버 원격 실행, 실험 queue, 결과 자동 수집, 성능 지표 기록 기능을 제공한다.

이를 통해 모델 학습과 평가 과정을 반복 가능하고 비교 가능한 형태로 정리했으며, 최종 프로그램에 적용할 모델을 선정하기 위한 실험 기반을 마련했다.
